# project/state — branch index

This branch holds the **current project state** after every session.
It is updated at the end of each turn (working rule, 2026-11-24).

## What lives here

```
research/idong100/                 # research tree: FINDINGS per turn + artifacts
  agents/01-chinese-web/           # vendor/product web research (turn 1)
  agents/02-products-software/     # products, host software, configs (turn 2)
  agents/09-xeyez-analysis/        # xeyez Windows stack disasm (turn 9)
  agents/10-rust-driver-draft/     # first Rust driver draft (turn 10)
  agents/12-extraction-sha/        # re-extraction + SHA manifest (turn 12)
  agents/13-rust-ros2-driver-draft/# ROS 2 driver design draft (turn 13)
  CONTEXT.md                       # verified facts baseline for any agent
  SUMMARY.md / README.md           # research-tree navigation
analysis/reports/                  # extraction + analysis outputs
  all_extracted_sha256.tsv         # SHA-256 manifest, 2475 files (turn 12)
  pe_inventory.txt / firmware_report.txt / config_dumps.txt / version_diff.txt
scripts/                           # tools: inno_bin_extract.py,
                                   # fetch_zip_members.py, analyze_extracted.py,
                                   # hal_disasm.py, live_slice_test.py, ...
deliverables/                      # PDF reports + Rust scaffold
  idong100_camera_research_turn12.pdf
  idong100_RUST_ROS2_DRIVER_DRAFT.pdf
  idong100-rs-scaffold/            # 45-file workspace skeleton (turn 13)
```

## Conventions

- One commit per session-turn: message format
  `state(turn N): <summary>` (N = conversation turn number).
- The turn-13 Rust scaffold is kept under `deliverables/` until it is
  moved to the workspace root in P1 (then it becomes the crate tree
  and is committed directly).
- Chat context backups do **not** live here — they are on the
  `chat/context` branch.
- Vendor firmware binaries are never committed (safety rule 6).
